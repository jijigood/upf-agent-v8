# 第三阶段 E5：同候选门控工程试点（2026-10-09）

已完成 WP09/E5 的首批工程控制：冻结 120 个同源候选，允许／禁止／未知各 40；同一候选在 A0–A4 累计策略及全部拒绝策略上比较，共 720 次策略判定。最终 A4 保留 40 个合法候选、拦截 40 个违规候选、将 40 个未知条件转人工；全量 734 项回归及 Ruff 通过。

本轮是离线诊断策略的工程试点。它使用未修改的完整 Validator 先产生诊断，再累计启用诊断类别；不是把线上 Gate 组件实际拆开运行的性能消融。完整诊断时间与来源读取均计入，不能把投影策略耗时解释为逐层取证节省。默认 Engine／Validator／模型生成头均未改。

## 输入、标签与执行

- 共享 N4 synthetic fixture；每类 8 个变体 × 5 个副本 = 40。副本交替使用 UPF-A／SMF-B；共享一个 source family，不称 120 个独立事故。
- 每个候选含两端身份和一个只读接口检查，共 3 步。候选是建议片段，不是完整故障调查方案；不计算方案 VPR 或 CDR。
- 允许类：state/interface/n4_enabled/mtu 的已知等值／存在前置条件。
- 禁止类：未知动作、已执行声明、物理来源 SHA 变化、错版、错上下文、错对象集、依赖环、已知为假的前置条件。
- 未知类：在物理 JSON 来源中删除／置空上述授权字段，再重新收集绑定；不是只篡改 Binding。方案声明 on_unknown=human_review，A4 在前置条件未知时暂缓建议并转人工。
- 控制预期从植入的条件生成；协议、120 个原始候选及输入、预期标签和 482 份输入文件 SHA 在任何方法评价前冻结。策略函数不读取预期标签。
- 当前引用以 R 证据为主。A2 的分类表包含既有 K/R/P 来源诊断，但这一矩阵没有充分覆盖 K/P 的适用性／配对采信，后续仍须增加控制。

## 累计检查的定义

| 策略 | 累计启用的诊断 | 本轮能说明什么 |
|---|---|---|
| A0 | 不启用拦截 | 原候选保留对照；仍无执行授权 |
| A1 | JSON 解析、动作白名单、参数、权限／效果类型及接口参数 | 格式和有限动作约束 |
| A2 | 加来源、证据引用、版本、有效期、K 适用性等诊断 | 本轮 R 来源／错版控制被拦截 |
| A3 | 加 scope/context/batch、对象／字段权限 | 当前对象集与上下文控制被拦截 |
| A4 | 加执行声明、目标假关闭、DAG、前置条件等全部诊断；未知前置条件转人工 | 本轮全部允许／禁止／未知控制符合预期 |
| reject-all | 所有候选一律 blocked | 低错受率不能代替可用性 |

`policy_decision` 输出只是离线建议判定，所有策略 execute_authorized=false，不将 A0–A3 接到生产入口。未知的新诊断代码在 A4 拒绝，完整 Validator 返回无效却没有诊断时也拒绝；已有硬违规优先于未知条件。物理 SHA 错／版本错会使前置条件同时未知，但仍 blocked，不能转人工后当作合法候选。

## 实际结果

`e5-pilot-001`，每行分母都是同一批 40 个对应类别候选。

| 策略 | 禁止类错受 / 40（URR） | 合法保留 / 40（VAAR） | 未知正确转人工 / 40 | 合法误拒绝 |
|---|---:|---:|---:|---:|
| A0 | 40（100%） | 40（100%） | 0 | 0 |
| A1 | 35（87.5%） | 40（100%） | 0 | 0 |
| A2 | 25（62.5%） | 40（100%） | 0 | 0 |
| A3 | 15（37.5%） | 40（100%） | 0 | 0 |
| A4 | 0（0%） | 40（100%） | 40 | 0 |
| reject-all | 0（0%） | 0（0%） | 0 | 40 |

A0–A3 均把 40 个未知候选保留为建议；A4 将这些候选全部暂缓。原 Validator 对允许／未知两类共 80 个候选仍判为结构合法，因为有限 on_unknown 出口允许条件性只读计划；A4 的三值建议判定是新增离线策略，没有把原 Validator 的合法条件计划改成硬违规。

这 0/40 是同源工程控制结果。重复候选相关，不套独立伯努利的一侧风险上界；confidence_bound、独立事故数、VPR、CDR 为 null。没有专家 Gold、现网安全或因果／延迟优势声明。
