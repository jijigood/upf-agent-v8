## 修订范围

首批失败包括模型省略依赖、缺少适用知识引用及证据 SHA 不符合 schema。共同方案头改为 `v8-plan-head-2`：生成指导 schema 要求每步显式输出 `depends_on` 和 `evidence`；提示词明确同对象身份依赖及配置检查的 K 类知识要求；输入提供由已有 evidence_id / revision / source SHA / locator 构造的可复制 citation，并展示 binding 中已有的适用性 receipt。

这些改变只发生在生成前，不修改输出原文，不为模型补写步骤、依赖或证据，不额外读取工具来源。四方法同用第二版头；IR、Translator、Validator、action registry 和参考匹配规则保持不变。`common-head.json` 保存实际指令及 schema/registry 指纹，各请求仍保存完整 trace。

服务请求仍使用 `response_format=json_object`，生成 schema 随提示提供，属于生成指导，并非服务端强制 schema 解码，因此不能保证所有引用或字段正确。剩余解析失败正说明这一边界；后续受约束生成须另行验证和登记。

## 第四版服务端结构化输出

本地 vLLM 的接口实现支持 `response_format=json_schema`，第四版只对共同方案头使用该接口；原 P5 的自主规划、参数修订仍使用 `json_object`。服务端 schema 固定可信上下文、顶层字段、最多 8 步、目标对象；动作分支限定 action registry 的参数、权限与效果，每步显式填写依赖和证据。证据引用限定为该方法已获得的完整 citation，不用模型抄写任意 SHA 或新增来源。未获得证据时引用列表只能为空。

Schema 保留全部方法可见引用，包括无适用目的的 K；不会按 Gold、Contract 状态或事后验证结果过滤给模型。角色、步骤依赖含义、知识目的/版本/时效、权限字段、真实来源、引用对象及自然文本语义仍须独立验证；结构化解码通过不等于诊断有效。输入 Schema 的具体约束保存在每次实际 request trace，通用规范与指纹存于 `common-head.json`；失败不会自动降级、重试或补写文本。
