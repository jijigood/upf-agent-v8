# E1 输入扩量与四方法校准实验验收

日期：2026-10-11（Asia/Shanghai）。本轮继续完成真实输入采集、四方法工程校准、逐份原文与运行成本核验。**输入规模已补齐，四方法工程校准及逐份复算已完成；正式独立 E1、领域 Gold 与真实双评仍未完成。**

## 输入与采集事实

当前60份文件案例＝24份旧 dev＋12份 validation＋24份 heldout 候选。旧 dev 与上轮3份新 validation 保留。本轮新增9份 validation 和24份 heldout，正常材料均来自实际隔离 Open5GS 2.7.6／UERANSIM 3.2.7 运行，不从 Contract 自动生成专家答案。

| 集合 | 实际条件与数量 | 来源与使用限制 |
| --- | --- | --- |
| dev | 24份既有开发案例 | 已参与开发；同一个来源／结构组件 |
| validation | 请求过滤、回复过滤、ogstun 管理关闭，共12份 | 含原3份及新增9份；同一个来源／结构组件，重复采集相关 |
| heldout | 网关地址缺失、回复黑洞路由、回复策略禁止，各6份 | 新故障族，共18份；三个来源／结构组件，尚未发送模型 |
| heldout 边界控制 | MTU576但小／大探针均正常，6份 | 第四个 heldout 组件；不能作为连通性故障的正例 |

本轮34次实际采集尝试，33次符合各自预登记的内核状态与探针效果；另1次低MTU导致大探针失败的假设未成立，记录保留。第一批已完成的27份输入复制到第二批时，逐文件验证来源和目标 hash 相同，不重复计作新试验。新的边界控制协议在新6份采集和任何模型输出之前登记；失败前序、协议变更说明及两版原始采集均保留。

每次采集均保存基线与恢复探针、独立内核读取、正常日志／配置／接口／路由／探针／抓包，以及模型不可见的注入真值。采集工具清理状态并重新建立 UE 会话后的恢复不能称作 Agent 修复或 MTTR。操作仅作用于本轮带所有权标记的隔离容器、内部 Docker 网络与其私有内核状态。

heldout 更新了用户面网段和隔离桥地址，仍使用相同核心 loopback 布局与上游软件镜像。60份形成6个来源／结构组件，大小为24、12和四组6；不是60个独立故障来源，不能据此宣称跨平台或新拓扑泛化。正常材料的 `synthetic=false` 只说明实际受控来源，`corroborated=false` 保留未审状态。

[来源核验](../../runtime/v8-next/e1-experiments-20261011/source-audit-001/summary.json)复算34次独立读取与探针，核对33份新案例的原始副本、实际字段投影、27份复制回执及抓包记录形状。抓包的 snaplen 截断单独计数，不当作完整报文内容；组织者资料与模型可见数据分开。

## 真实模型与工程校准

实际使用本机既有 Qwen3-30B-A3B-Instruct-2507 服务，23份物理权重／tokenizer／配置文件 SHA、进程 PID／启动 tick、真实启动参数和 GET `/models` 身份均有[部署回执](../../runtime/v8-next/e1-experiments-20261011/actual-deployment-001.json)。没有重启服务或切换模型。预检发现 GET 返回的创建时间与 permission ID 每次变化，只修复身份比对的易变字段及本机代理绕行；模型名、路径、能力、权限、物理权重和实际进程仍核验。

核心文件仅 `e1_formal.py` 的部署核验簿记发生本轮变动，当前核心 SHA 为 `74e24791c7955ad58e09da4eb150fca100202264daaac6f6cc50feee5961d538`。[变更范围回执](../../runtime/v8-next/e1-experiments-20261011/code-change-scope-001.json)确认规划器、生成器、Validator、compiler、graph 和 registry 未根据模型答案调整。首次预检失败发生在输入冻结和生成之前，失败日志另存。

单独的工程入口只加载12份 validation，在首次生成之前复制可见输入并冻结代码及部署回执。四方法为 DirectLLM、原生 P5、v8-no-graph 和 v8-full，均使用现有 CommonPlanHead 与8工具／8模型／3轮／180秒预算，方法按预登记 Latin 轮换顺序运行。既有共同 head 和允许动作模板是本次比较范围，不可据此证明自由规划或模板以外的能力。

`reference_pass`／VPR／分支匹配保持 null，未构造新 CaseGold，也未调用正式数据门槛后的 heldout。机械检查仅验证现有 schema、证据、权限和步骤依赖，不能替代领域语义有效性。输入未获专家核验时，系统可能保留补证／人工复核／停止流程；机械通过率不能解释为故障原因定位或合理处置成功率。

[实际运行](../../runtime/v8-next/e1-experiments-20261011/validation-engineering-002/summary.json)完成48/48，运行错误0、未知成本0；首次生成至末次生成期间可见输入和代码 hash 均未变。实际72次模型调用＝48次共同方案 head＋24次 P5 原生规划调用；120次工具尝试，输入607,577 Token／输出34,006 Token。

## 人工事实与后续顺序

36份新案例缺独立 Gold，60份当前 canonical hash 的真实双评批准均为0。24份旧参考仅是历史未审开发材料。120行 Gold 双评空表、60份专家编制资料已交付；其中正常证据和私有真值可供专家先独立编制合理步骤与约束，不得把现有 Contract 的步骤自动转成批准答案。

独立 Gold 应结合真实运行观测、适用版本手册及专业判断，注明必须检查的状态、步骤依赖、可接受替代、禁用动作、停止条件与适用范围。若事实所需动作超出现有 IR，不应为了让当前系统通过而删减 Gold。真实来源和评审专业能力仍是人工事实。

[正式拒绝回执](../../runtime/v8-next/e1-experiments-20261011/formal-gate-001.json)确认在模型探测与正式冻结前拒绝缺参考／真实审核的资料，heldout 模型消费为0。后续顺序：独立 Gold与真实双评／必要仲裁→另版正式 validation 冻结与执行→原文真实语义双评→固定版本单次 heldout→正式 VPR 和按来源／结构组件配对统计。工程校准不能改名为正式 E1 成绩。

本轮完善输入与执行证据链，尚不能关闭 WP06、WP09 或 WP11 的领域质量总项。E2–E7 历史实验和133,789行导出仍保留；此前16,317份原始证据及3922＋66＋477份三轮冻结副本已逐 SHA 核对一致。
