# 公开数据集补充 E1 案例的可行性核验

日期：2026-10-11。结论：建议可以补充独立于本项目开发过程的公开任务和作者参考，支持另行开展外部基准实验；不能直接补齐当前36份新 UPF 案例的独立 Gold，也不能代替本项目正式协议要求的实际双人审核。

当前已有60份输入（24 dev／12 validation／24 heldout候选），缺的是领域参考、适用知识与真实审核，另外来源／结构多样性仍有限。应把数量、公开参考标签、UPF步骤 Gold、真实评审分别核算。

## 实际核查范围与结果

## 参考可以怎样使用

沿作者定义做外部公开基准时，可以采用其已发布的参考与对应指标，报告公开参考匹配、工具顺序或摘要相似度；不必为了启动每项外部测试先重新逐条建立本项目的双评Gold。作者参考的存在本身不证明本项目60例已获真实审核，也不证明自然语言方案能在UPF实网有效执行。

Telco的gold_path是有序工具列表，可转换成链式依赖；它不是现成的任意Gold DAG、替代方案集合或UPF技术事实。只输入query与允许的初始材料，不能把agent对话、gold_path、gold_summary或intent答案当作模型可见上下文。论文也说明从初始query评价，不重放完整合成对话，尚不评价完整闭环网络操作。

TeleCom输入本来就包含根因和处置建议，沿原协议应保留这些题内信息，并明确评价的是已知处置知识到步骤的转换；不宣称盲诊断能力。best_answer仍保持模型不可见。

## 当前代码的适配缺口

项目任务模板限于UPF N3／N4、manual_operation、log_observation，动作注册表只有身份、接口、配置、日志、映射、补证、人审及有界变更建议。实际Telco gold_path含coverage_map、optimize_cell和create_ticket；这些工具没有对应实现，不能仅改工具名或删掉写操作就声称复现原基准。若改变只读任务／参考，应另命名派生任务并独立统计。

现有未审校准48份输出均停在身份核验、日志读取和补证，四方法机器检查差异0。导入外部JSON本身不会让现有共同head获得无线侧知识、外部工具或可采信证据。下一步需定义独立的外部任务与工具／计划接口，公平对接各方法，明确当前实现不支持的案例和失败分母；不要把模板补证结果当作工具流程完成。

补充逐份审计已确认：12份校准任务全为log_observation，96个重复绑定实例的物理来源校验全部通过，但corroborated全为false、准入证据为0；实际服务端Schema固定5槽，四方法动作／目标顺序全部相同。原文有23种文本组合，操作字段只有event_type填值／null两种；Reference Match和VPR未启用，均为null而非0分。因此应先处理证据准入与计划接口的表达范围，并完成真实Gold；只增加题量或给现有参考加审核标记不会自动补齐这些条件。完整结果见[E1方案区分度与失败机制审计](E1方案区分度与失败机制审计_20261011.md)。

## 建议的后续顺序

UPF主实验优先完成上述区分度审计与12份validation的来源／知识／Gold核验，暂不继续扩充题量。下面列的是外部数据适配与正式实验的衔接顺序；公开数据并非当前主实验的首要依赖。

1. 先建立外部基准输入／参考的原文、commit、SHA和来源分组索引；TeleCom的5份只作小规模连通性试验，Telco按不同Blueprint抽取校准样本，其他Blueprint留作外部测试，不随机混合同族30份变体。
2. 定义并冻结外部接口和评价协议，以作者参考开展单独的四方法工具流程／步骤对照。公开基准及派生只读任务分别报告，不能并入UPF正式VPR或声称全新私有heldout。
3. UPF主实验继续基于现有新采集的正常观测、私有注入真值和适用手册构建36份独立参考，保持120行双评空表与实际评审0的真实状态；不用LLM答案或当前Contract自动批准。
4. 收到真实Gold与审核后，按正式validation冻结／运行／原文复核，再单次消费原24份heldout。若版本或材料改变，另版冻结和验证。

本次是资源可行性核验，未修改已有60例、业务代码、plan或4492文件冻结交付。没有将外部标签登记为已审核UPF Gold，没有启动正式E1或任何模型实验。
