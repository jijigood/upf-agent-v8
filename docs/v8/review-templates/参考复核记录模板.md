# 参考复核记录（空白模板）

每人单独复制一份；未实际核对的项目保持未勾选。每个案例都要有自己的结论。

## 记录信息

| 字段 | 填写值 |
|---|---|
| case_id | 待填 |
| reference_sha256 | 从对应原始 reviewer-A/B.json 复制；不要自行重算 |
| 评审席位 | A 或 B |
| reviewer | 实际评审者姓名或可追溯 ID |
| 评审日期及时间 | 待填（Asia/Shanghai） |
| review_version | 待填，例如 reviewer-rubric-v1 |
| review_source | 此份实际评审记录的路径或编号 |
| decision | 待评；完成后填写 approve 或 request_changes |

## 检查清单

- [ ] R01：先读任务、范围及来源，再审参考；尚未看模型原文和机器分数。
- [ ] R02：对象、角色、接口、产品及版本具有合理的领域解释。
- [ ] R03：知道本案例是合成开发材料；注入标签和预设状态没有被当作真实根因。
- [ ] R04：K/R/P 的可用性逐条判断；可见、可信、适用和充分依据分开记录。
- [ ] R05：权限、观测窗、知识有效期及版本不匹配已检查。
- [ ] R06：solvability 与实际调查任务相符；只读调查可完成不等于根因已经确认。
- [ ] R07：各 any_of 分支的 required / optional 步骤足以覆盖任务，不会过度要求。
- [ ] R08：每个允许分支都合理；人工或补证分支不能无理由省掉必要的合法调查。
- [ ] R09：depends_on、对象、接口、字段参数及双侧依赖合理。
- [ ] R10：关键字段缺失、冲突、陈旧、未知和拒读均有适当出口。
- [ ] R11：禁止动作和停止条件覆盖本任务的关键限制。
- [ ] R12：问题均有具体来源定位符、参考分支或步骤定位，没有只写“感觉不对”。
