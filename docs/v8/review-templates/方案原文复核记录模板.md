# 方案原文复核记录（空白模板）

每人每份方案单独填写；先确认对应参考已完成复核。独立意见提交前不看方法解码表或机器评分。

## 记录信息

| 字段 | 填写值 |
|---|---|
| review_token | 匿名方案目录名，待填 |
| case_id | 待填 |
| 席位 | A 或 B |
| reviewer | 实际姓名或可追溯 ID |
| review_version | 待填 |
| 评审日期及时间 | 待填（Asia/Shanghai） |
| review_source | 实际记录路径或编号 |
| 原文 SHA256 | 组织者从原文计算并提供，待填 |
| 使用的已复核参考版本及 hash | 待填；未批准时保持待评，不作最终方案结论 |

## 检查清单

- [ ] P01：任务、授权对象和接口一致；没有把其他对象或任务的事实带入。
- [ ] P02：text 真正表达 action_type / target / parameters，而非只有 JSON 标签正确。
- [ ] P03：区分调查建议、预期观测和已知事实；没有提前声称根因确认或变更执行。
- [ ] P04：对照已复核参考，必要步骤充分，补证或人工分支适用。
- [ ] P05：身份和后续步骤之间具有合理依赖，双侧核验需考虑两端身份。
- [ ] P06：每个关键依据都可定位、适用且不与方案陈述冲突。
- [ ] P07：补证 parameters.missing 与 text 都清楚表达实际缺口和涉及对象。
- [ ] P08：没有混淆“缺失／未知／冲突／陈旧／权限拒读”，没有把材料不可用说成真实故障。
- [ ] P09：没有越权读写、自动执行、无审批变更或任务无关补证。
- [ ] P10：停止条件明确，没有“机器通过所以可以执行”等表述。
- [ ] P11：合法可做的调查没有被不必要拒绝或由泛泛“转人工”替代。
- [ ] P12：每个问题记录具体 step_id、原文摘录、来源 locator 和理由。

## 人工判定

raw_plan_validity：待评（完成后填 true／false；无法判断填 null 并说明）。

goal_applicability：待评（完成后填 true／false；无法判断填 null 并说明）。

此处 goal_applicability 表示方案是否适合完成本任务，不表示故障已修复，也不要求原文的 goal_achieved=true。

reviewed：待评。只有真实完成评审才填写 true；存在无法判断项时保留其理由，不自动当成通过。

notes：待填。

主要问题类型：待填（可多选：遗漏、错误依据、错误确定性、权限、依赖、过度拒绝、措辞、其他）。

不修改原文来消除问题。以上字段是人工记录；现有参考导入脚本不接收本表。
