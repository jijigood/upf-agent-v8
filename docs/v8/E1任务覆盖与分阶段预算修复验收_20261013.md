# E1 任务覆盖与分阶段预算修复验收

日期：2026-10-13，Asia/Shanghai。工作目录：`runtime/v8-next/e1-task-coverage-repair-20261013-001/`。本轮任务覆盖与预算保护的工程修复、小规模实测及独立复算已完成；未启动正式 E1 或 heldout，未批准领域语义或证明v8质量领先。

## 修复范围和实现

新增显式可选 profile `task-covered-readonly-1`，不改变 legacy、verified-runtime 或 expert-revision 的默认行为及正式人审门槛。

1. 将原公开用户问题中已经要求的接口、INPUT／OUTPUT、探针、两侧捕获、日志、固定版本手册及比较编为 `data/task-request.json`。绑定问题、权限及产品版本 hash；它是未批准的作者任务定义，独立于组织者 Gold，不含故障原因、注入操作或专家批准。只支持本次明确问题，不对任意问题猜测义务。
2. 生成前提供同一任务清单及合法动作选项，模型在 `task_coverage` 声明每项要求对应的实际步骤。顺序、合法替代、引用和附加依赖仍由模型决定，不提供 Gold DAG 或评分。
3. 独立 Validator 重新检查实际动作、对象、参数、所引字段及覆盖声明。少步骤、错对象／方向、假覆盖、缺原文字段、错任务 hash 均不能发布。结构合法、任务覆盖与专家技术正确性分开报告；覆盖通过不表示诊断或动作已执行。
4. 总预算仍为180秒／8模型／8工具／3轮／3072输出。首版120秒预留在实测132.25秒共同头下不足，最终head-2预留140秒，原生阶段可用40秒；原生模型请求余量不足20秒时在实际派发前阻止，不启动注定只有极短余量的请求。最终阶段使用未花掉的总余额，不增加总预算。单独记录原生、输出及总耗时；保留原生阶段超时／降级、阻止的请求和未知费用，不把共同头成功等同于P5原生闭环成功。
5. 新 wire 在生成前声明固定的只读、未执行、不可执行和未知时补证默认值，解码 Schema 不重复这些常量。人工动作仍显式填写human／suggestion。每步文本／待核验判据最多12字，停止条件最多4条／每条48字；本任务不输出附加preconditions，用实际身份依赖与未知出口表达边界。转换器只解析原文和预定义类型默认值，不补步骤、证据、参数或任务覆盖；原文及span保留。

## 一个需要澄清的旧失败判断

原用户问题明确允许通过既有 session 原文核对 UE 日志。选中的两例旧输出已包含对应动作和同源字段，因此“没有单独 READ_LOG”不能统一等同于“UE日志要求未覆盖”；是否真正表达了核对意图仍需语义审核。独立任务检查据此保留替代路径，主要共同缺项为 **UPF日志核对**。旧验收和原专家意见不覆盖，本说明补充评价口径。

## 小规模验证协议

仅使用原 validation 的 N001、N003，分别覆盖既有两种结构族，仍只有一个相关来源组件。正常资料、原问题及旧未批准参考保持原样，新增独立案例0。新 task-request 独立存于模型可见输入；参考仍位于 organizer-only，仅在生成结束后评分。

预登记两例×四方法8次，保留全部原文、失败和费用，不对单方法选取重试，不从 heldout 调整规则。先完成真实保存上下文的正反控制、请求语法和长度预检，再运行实际模型。原48份矩阵不重写，校准匹配仍为开发指标，正式VPR=null。
