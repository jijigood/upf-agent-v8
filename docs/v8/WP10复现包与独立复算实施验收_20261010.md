## 5. 如何在另一个目录复现

先在项目根目录解压，目标目录必须尚不存在：

```bash
.venv-v8/bin/python scripts/v8_wp10_bundle.py \
  --extract runtime/v8-next/wp10/synthetic-bundle-005/wp10-synthetic.tar.gz \
  --output /tmp/upf-wp10-new/synthetic
```

进入解压目录，安装固定依赖并执行：

```bash
cd /tmp/upf-wp10-new/synthetic
uv sync --locked --no-dev --python 3.11
.venv/bin/python scripts/v8_bundle_replay.py \
  --output runtime/v8-next/phase3/wp10-reproduce-001 \
  --fresh-cpu \
  --deny-root /home/huangxiaolin/upf-agent-v8
```

依赖已经缓存时，可使用 `uv sync --locked --offline --no-dev --python 3.11`。本次两个独立环境均利用公开依赖缓存完成离线安装；没有缓存的新机器仍需先安装 Python 依赖，本包不包含 wheelhouse。

只回放历史结果时去掉 `--fresh-cpu`。追加 CPU 执行时，输出必须位于包内 `runtime/v8-next/phase3/`，符合 E5 的既有实验命名空间约束。重复执行使用新输出 ID，不覆盖已有结果。

离线执行期间禁止 socket 连接和原项目目录的 Python 文件读取／目录访问。仅允许标准库的精确 `uname -p` 查询读取内核硬件元数据，其他子进程仍拦截；验收报告区分该查询与被阻止的操作。此机制是 Python audit 保护，不是操作系统沙箱。

E3 原始数据库先复制到新工作目录再读，以避免 SQLite 创建或更新 WAL/SHM。原始包内全部文件在复算前后核对 SHA；验收证明包内历史数据未改变。

实际 E2 附件按同样方式单独解压、安装和执行，不加 `--fresh-cpu`。其原始缓存绝对路径保持为冻结元数据，通过 `--seed-cache-root`／包内缓存目录定位同名文件并核对原 SHA；不同原路径有相同文件名时拒绝迁移，不能偷偷换缓存。
