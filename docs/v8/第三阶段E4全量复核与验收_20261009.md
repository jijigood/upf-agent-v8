## 成本与解释边界

每组、每方法分别保留 fingerprint、index_integrity_audit、observed_read_audit、propagation_recompute、fallback 与 full_evaluation 的累计秒数；初始化另存 index、初始评估、初始读集认证及 CPU。复核包 `groups/<组>/<方法>/cost_totals` 和 `initialization` 可直接核对。

- 主矩阵 fallback=0；损坏索引、实际读集及中断恢复由先前 90 类边界/18 项安全控制覆盖。fallback 秒数是 propagation/recompute 的子集，禁止重复相加。
- 所有 Local 在 S-10、S-50、M-50 上均有负收益；S-50 的 Full/L3=0.690，即 L3 更新约慢 45%。保留这些负例，不宣称局部更新普遍更快。
- 标量 revision/value 更新通常改变状态 basis，因此本矩阵不能把 L1/L2 的微小时延差解释为截断收益。独立稳定输出控制才显示 XL 重算状态 501→1。
- cold_seconds 指运行中进程的新 evaluator 初始化，没有清空 OS 缓存；RSS 是同一进程累计峰值，不能拆成方法独占内存。
- 单 worker 是执行模式；主机与 WP08、参考修订及 E5 的开发/测试共用，结果为该条件下的观测值，不支持独占主机或纯算法因果结论。
- 四 worker 吞吐为 null / not run。单请求延迟验收无需把并行吞吐混入；如需容量结论，再另冻版本、独立执行并报告。
