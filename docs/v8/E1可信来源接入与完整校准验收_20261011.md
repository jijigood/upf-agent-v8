## 已修复的输入与来源链

`recollection-003` 对 validation 的三个既有故障条件各重新采集四次：内层请求过滤、内层回复过滤和 ogstun 管理关闭。每次在自建隔离 core／UE 容器内注入，独立读回验证，然后在同一故障窗口通过正常读取接口采集两侧抓包、三个 filter 链计数、Linux 接口、日志与五次 UE 探针。私有注入命令、故障标签及独立验证不进入模型可见目录。12 次故障验证、采集准入、恢复和清理均通过；恢复是实验 harness 的资源处理，不是 Agent 的修复。

## 报文观察范围

新增普通 IPv4 ICMP 回显观察解析，支持 Ethernet、Linux cooked v1／v2 和 raw IPv4 的经典 PCAP，保留位置、时间、端点、类型、标识、序号与载荷 SHA。两侧对应按这些字段和有界时间一对一匹配；私有对应结果供专家编制使用，不作为模型的参考答案。未知协议和分片明确跳过，未验证 IP／ICMP 校验和，未解码 GTP 内层或 PFCP 会话，不推断应用送达、丢包概率或因果。ICMP 字段依据 [RFC 792](https://www.rfc-editor.org/rfc/rfc792)，Linux cooked 帧布局依据 [libpcap 原始定义](https://raw.githubusercontent.com/the-tcpdump-group/libpcap/master/pcap/sll.h)。

既有 `COMPARE_CAPTURE_WINDOWS` 的动作语义仍为位置、时窗和完整性；新增普通 ICMP 观察不将这个动作扩大成会话／送达验证。
