## 根因与修订

旧 `plan_cases.py` 按对象构造身份／接口／配置，再添加补证或人工分支，遗漏跨对象动作。参考匹配只检查 `required` 中已列出的项目，因此即使某方案缺映射，也可能匹配旧参考；生成头自行包含正确动作掩盖了这个缺口。它是参考定义不足，本轮不改模型提示或 Validator。

新 `reference_revision.py` 只从任务的 N3/N4 模板、两对象路径与原参考生成修订，不读取模型输出推断要求。每个允许分支加入：

```json
{
  "pattern_id": "peer-mapping",
  "action_type": "VERIFY_PEER_MAPPING",
  "target": "UPF-A",
  "parameters": {"peer_object_id": "SMF-B"},
  "depends_on": ["id-dd579bea", "id-5e038450"]
}
```

一个动作覆盖双侧核验，不要求分别对两端重复两次动作。调查分支保留原身份／接口／配置／补证模式；`review` 分支补两端身份锚及条件性映射调查，继续保留 HUMAN_REVIEW 出口，使其不能仅凭一个人工动作绕过题目的双侧要求。未知证据仍通过方案 `on_unknown` 停止／补证／人工处理，不把计划中的调查解释为已获得映射证据。

task、来源 hash、可解性、权限、时间、禁止动作与停止条件均保留。变化的参考不继承旧批准；`reviewed=false`。这 20 个参考是模型输出后的开发纠错，不能作为预冻结独立 Gold 或新的盲测结果。
