## 2. 人工复核顺序

先只打开审查包的 `public/`，不要打开 `organizer-only/` 或实验的 `private/`。本包不是匿名评审包，方法名称可见；它只隔离注入真值，不能称为已完成盲评。

1. 在 `input-index.json` 找一个item，打开对应 `snapshot.json`。确认状态、配置、两次探针、抓包和当前窗口日志来自同一采集范围。进程S属于正常睡眠，T属于停止调度。
2. 打开 `flat-report.json`、`joined-report.json`、`graph-report.json`。每个候选的 `evidence_ids` 必须能在该报告的 `facts` 中找到；沿locator定位原快照。规则形成的是候选，不能将rationale中的“路径候选”改成“已证明网络丢包机制”。
3. 检查方向。上行探针是UE到网关、下行探针是网关到UE；ICMP请求8／回复0需同时核对外层和内层地址。仅看到INPUT之前的包不说明目标应用收到。
4. 检查PFCP方向。两端心跳请求序列号空间独立，只能按反向端点＋同一事务序列号＋时间顺序匹配回复，不能因为两边各有包就判双向事务成功。缺少区分证据时unknown是合法出口。
5. 检查graph报告的 `graph_query`。候选→联合节点→每个所需事实的边应完整；图查询不应截断。边中的派生关联不等于独立佐证。比较joined与graph时，证据和规则应相同，不能把flat缺少联合规则的损失计作图算法收益。
6. 如审会话关联，查看 `e7-pilot-session-mapping-003/round-NNN.json` 或 `e7-full-session-mapping-003/round-NNN.json`。检查CP/UP F-SEID、建立与修改请求／回复、序列号、时间、N3 TEID、当前唯一UE IP及RAN绑定／通告地址。双向字段匹配与对端配置正确是两个判定；某条声明的通告地址即使与包匹配，也可能与实际绑定地址冲突。
7. 检查所有 `execute_authorized`、`agent_execution`、`application_acceptance_proven`。本轮没有Agent修复；harness复位和ping恢复不能算模型执行、MTTR或完整PDR/FAR/QER安装成功。
8. 第一遍意见落盘后，组织者再对照private中的独立故障核验和健康恢复。真值符合不自动证明每句理由成立；代码正确但理由误导仍应记录。

组织者优先核对主批round-049／051／053的unknown、RAN地址错配与健康控制，并对照8秒补证中相同证据模式。先独立记录每份理由，再进行跨批分析。补证延长的是会话采集，`capture_to_ranking_seconds` 未覆盖这额外5秒；报告时分开使用完整快照窗口。不能把补证9/9写成原主批60/60，也不能把心跳方向命中写成完整会话安装成功。

## 3. 怎么记录

复制 `public/reviewer-1.csv` 到个人工作目录填写，第二位人员使用 `reviewer-2.csv`。原模板不改，两席不能由同一人或自动脚本代填成独立评审。

- `item_id`、`input_sha256`、`material_sha256`：保留原值。input hash绑定正常快照，material hash绑定快照及三份报告的完整文件清单；不能只确认输入而忽略输出版本变化。
- `reviewer`、`reviewed_at`、`review_source`：真实姓名或代号、实际时间、真实记录路径或来源。
- `decision`：`approve / conditional / revise / reject`；理由不足不能仅因为自动Top1正确而批准。
- `evidence_locations`：文件、fact ID、包序号／时间或日志行，例如“graph报告f020，packet_index=3；快照packet_captures/session”。
- `rationale`：说明支持哪项事实、哪些句子过强、缺少什么证据或需要什么修订。

首先覆盖每种不同证据模式及未知／错配案例，其余重复轮按批准的采样协议确定范围。完整保留全部轮次不意味着要求把相同规则的重复输出机械重读五遍。真实双评分歧另存仲裁，保留双方原意见。

## 4. 本地复算

CPU脚本使用项目Python3.11环境，不调用模型，也不执行网络变更。以下命令以项目根为工作目录，输出目录必须为新的实验ID。

```bash
.venv-v8/bin/python scripts/v8_formal_readiness.py \
  --cases runtime/v8-next/phase2/review-closure-full-001/cases \
  --output runtime/v8-next/remaining-experiments-20261010/formal-e1-readiness-new

.venv-v8/bin/python scripts/v8_e7_evidence_audit.py \
  --dataset runtime/v8-next/remaining-experiments-20261010/e7-evidence-pilot-001 \
  --output runtime/v8-next/remaining-experiments-20261010/e7-evidence-pilot-audit-new
```

会话分析以冻结003代码执行，禁止用尚在修改的同名脚本替换版本：

```bash
.venv-v8/bin/python \
  runtime/v8-next/remaining-experiments-20261010/session-mapping-code-003/scripts/v8_e7_session_mapping.py \
  --dataset runtime/v8-next/remaining-experiments-20261010/e7-evidence-pilot-001 \
  --output runtime/v8-next/remaining-experiments-20261010/e7-pilot-session-mapping-new
```

```bash

  /新目录/package/scripts/v8_e7_evidence_offline.py \
```

此命令核验附件manifest并实际重算三方法和会话字段，不访问原项目或推理端点。Python audit guard用于防止意外访问，不是恶意原生代码的操作系统沙箱。附件含组织者真值，仅用于本地复现；给第一遍评审只提供public材料。

若重新采集网络实验，必须用新的输出ID和固定Docker镜像，通过新pilot后再扩量；runner仅创建带自身owner标签的内部网络和容器，退出时按标签回收。不要沿用旧注入、清理记录作为新采集证明。
