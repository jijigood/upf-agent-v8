## 新定位的 K 引用接口缺口

使用实际批次冻结源码，重建 48 个保存上下文的完整 Schema，结果见 `manual-citation-reachability.json`／CSV：48/48 上下文有准入 K，0/48 有能引用 K 的合法动作分支。

原因是旧 `CHECK_CONFIGURATION` 固定检查 `n4_enabled`，而本轮只读权限包含 `instruction`、日志和领域库存，未授权 `n4_enabled`。因此配置分支被合法屏蔽。`CHECK_IDENTITY`／`HUMAN_REVIEW` 的 evidence 数组上限为 0；现有领域读取动作仅接收正常 R。资料可见与动作可引用是两个条件，本版只满足前者。

所以专家发现“47 份可解析方案未绑定 K”已复现，但不能仅据此归因于模型忽略手册或能力不足。应新增独立、只读、对象／版本作用域内的手册原文核对动作和相应 Validator，支持实际 `instruction` 原文与定位；不能通过放开没有事实依据的 `n4_enabled` 权限来绕过问题。此实现尚未完成，本次没有改业务代码。

## 完整移交包及核验

新包：[portable-e1-delivery-001.tar.gz](../../runtime/v8-next/e1-review-intake-20261012-001/portable-e1-delivery-001.tar.gz)。原逻辑文件共 18,102 个，内容按 SHA 保存为 2,144 个短路径对象；原 manifest 字节 SHA 保持 `c1ad6143bdfa23972a61b3b3ba522d4e3022abc3e3c13a4e6e703f1945ec92d2`，没有删掉重复逻辑文件或前序失败。

压缩内部 2,144 个对象和元数据逐字节核验一致，另在新目录恢复并核验 18,102 个文件。此包用于补足移交，不代表已在对方 Windows 目录恢复完成。解压后，标准 Python 可执行：

```bash
python delivery_tools.py verify --expected-manifest-sha256 c1ad6143bdfa23972a61b3b3ba522d4e3022abc3e3c13a4e6e703f1945ec92d2
python delivery_tools.py restore --output <尚不存在的新目录>
```

`verify` 直接校验短路径对象，不需要恢复深层目录。原逻辑位置在 `manifest.json` 的 `files` 中，实际内容为 `objects/<sha256>`，可按此索引读取单文件。`restore` 只写入新目录；现有目录不会被覆盖。工具仅用标准库，不调用模型或 UPF 业务接口。

压缩文件、内部内容和恢复核验见 `portable-delivery-receipt.json`、`archive-verification.json` 与 `portable-delivery-restore-verification.json`。专家意见正式来源、修订项和正式门槛分别记录，避免把一项完成状态替代另一项。
