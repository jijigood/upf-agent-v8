# E1 方案区分度与失败机制审计

日期：2026-10-11。结论：采纳“先审计区分度，再完善现有参考与审核，暂不扩大案例数量”的优先级。现有校准的无差异结果主要来自任务范围、证据准入和共同生成 Schema 的叠加限制；当前不能把它解释为四方法领域质量相同，也不能期待只补 Gold 就自动出现规划收益。

本次复算 `validation-engineering-002` 中12份 validation、48份实际原文及保存的模型请求；没有读取 heldout 案例内容、调用模型、修改业务代码或更改证据／Gold／审核记录。使用实际运行保存的代码副本重放，而非替换评价器。1229份既有运行清单文件逐 SHA 一致，解析与完整 Validator、证据准入、实际请求 Schema 和 workflow 均48/48复现。

## 为什么没有步骤结构差异

在 [plan_capabilities.py](../../src/upf_agent/v8/plan_capabilities.py) 中，准入条件是物理来源校验通过且 `corroborated=true`。本轮物理校验通过，但确认标记为 false，因此所有 R 仍作为识别缺口的材料进入请求，不能作为已知事实引用。正式 Gold 的双评批准与模型可见证据的准入标记分别管理：仅补上参考和 `reviewed=true` 不会自动补齐可采信证据、适用手册与双侧映射。不能为提高分数直接把标记批量改成 true。

[plan_generator.py](../../src/upf_agent/v8/plan_generator.py) 的 `_workflow_schema` 使用 `prefixItems`、`items=false` 及相等的 `minItems/maxItems` 固定任务步骤。这里不只是提示词倾向相似；实际48个服务端请求都携带硬性5槽约束。对 `log_observation`，即使未来 R 获准引用，模板仍主要限定为身份／日志调查，而非任意故障规划。代码的生成清单已声明 `autonomous_action_sequence_claim=false`，模型职责是调查文本、适用引用和出口选择；本轮应沿这个工程范围解释。

原生方法确实运行不同路径：48次共同方案头调用之外，P5实际多24次原生规划调用；工具尝试也不同。不能说 P5 没有运行或四方法整个过程相同。但最终共同头读取的证据内容相同，任务槽位相同，现有输入未激发跨节点路径和 K／P 机制，最终结构指标因此缺少区分空间。共享的最大预算与不同的实际消耗也应分别报告。

## Validator 能证明到哪里

完整 Validator 处理结构、上下文、作用域、权限、证据与前置条件等机器检查；其报告明确标注自然语言语义需要独立审核。本次另外对一份方案的内存副本作两个离线探针：仅将日志步骤文字改成无依据的“根因已确认、已修复及完全恢复”，机器检查仍通过；将步骤依赖改成自依赖，则被 `dependency_cycle` 拒绝。

这两份是明确标记的人工反例探针，不是模型实际输出，不加入48份分母、不当作 Gold，也没有改写原文。它们说明机器合法性不足以判断文字中的领域结论；并不证明真实48份都包含错误断言。[探针回执](../../runtime/v8-next/e1-discrimination-audit-20261011-002/validator-offline-probes.json)。

## 后续工作顺序及完成标准

1. **P0：区分度审计。** 本次原文、证据、Schema 与机器评分审计已完成。真实可解比例、措辞正确率和方案分支适当性尚无独立 Gold／专家审核，保留未知；这些缺项不能用本次审计自动填完。
2. **P0：先完善12份 validation。** 专家分别核对正常观测、注入事实、对象和产品版本、适用手册，建立必要步骤、合理替代、未知出口与禁止操作。为模型可见材料补真实来源核验与适用知识记录，同时独立编制和双评 Gold；二者不相互冒充。整理草稿可以自动化，实际审核者与仲裁不得虚构。
3. **P1：在 dev／validation 上确定比较目标。** 若比较受控流程质量，保留当前 head，评价文本、引用、缺口和安全行为；若要证明自主规划收益，先另版设计允许合理路径选择的共同计划接口，在权限与来源约束下检验其表达能力，再冻结。不能把现有固定槽位覆盖率当规划能力，也不能查看 heldout 得分后放松约束或删减参考以偏向 v8。
4. **P1：建立独立分层与冻结。** 参考先独立标记可解、补证／转人工、证据冲突和正常边界等任务；分别报告完整诊断／计划有效与合理补证结果。仍保留全部预定任务的失败、缺输出和不支持案例，不通过事后缩小分母提高成功率。已有60例源于相同受控平台并存在采集／结构相关性，依据既有来源核验只能支持限定范围的结果，不能宣称60个独立真实故障或跨平台泛化。
5. **P1：再做正式 validation 与 heldout。** 真实参考与审核完成、来源／结构分组检查通过，且模型、输入权限、接口、评价规则冻结后，运行正式 validation 并做原文审核；通过协议门槛后才单次消费24份 heldout。材料或规划协议变更均另版登记。
6. **P2：外部基准单列。** TeleCom 5例用于小规模适配；Telco按 Blueprint 整组划分并保留其真实工具语义。公开作者参考可以沿原任务独立评价，不必冒充当前UPF双评 Gold，外部结果不混入UPF VPR。E2／E3／E5可支撑证据与安全机制的贡献，但各自结论仍须落到实际数据和适用条件，不能用 E1 的零差值反推这些机制必然有效。
