## 原版失败与另版修复

版本1的新动作Schema采用step_id首字段，旧动作采用action_type首字段。紧凑解码固定属性顺序；选择step_id开头后，身份核验等旧动作分支即被排除。实际GrammarMatcher确认：step_id开头的身份步骤被拒绝，新隧道动作却可接受。原12次模型输出都重复同一隧道动作编号，未生成其依赖的身份步骤。

这批12/12能解析、0/12机械通过；共有12条重复编号、144条未知依赖、144条身份依赖缺失。实际模型18次、工具63次，输入117,402／输出18,695 Token。源码和输入运行期间未变，原文、费用、失败、411份批次文件及实际语法完整复算；随后使用其冻结源码再次重放一致。原失败未补编号、依赖或步骤，也没有从分母中删除。

版本2统一每个动作分支的 `action_type → target → step_id → text` 顺序，保留自行选择1～12步及依赖，没有新增必需步骤槽位。除Schema语义摘要外，增加实际序列化摘要，避免规范JSON摘要忽略属性顺序；每次实际EBNF另行重编译核对。独立校验也补上过滤链读回返回码非0的缺证门槛。
